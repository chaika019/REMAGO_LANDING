# RTV: видео и S3-совместимое хранилище

## Текущее состояние

В этой среде подключены **12 исходных роликов** из `../video` (525 049 938 байт,
около 501 MiB). Это локальная проверочная версия, **сжатие ещё не выполнено**.
Полноценные FFmpeg/FFprobe отсутствуют, загрузка инструмента недоступна из-за
ограничений сети, Docker недоступен. AWS CLI и параметры хранилища не заданы.
В `reports/video/encoding.json` зафиксированы реальные размеры, а не оценка экономии.
Выгрузка исходников в S3 намеренно отклоняется скриптом: сначала требуется кодирование.

Каталог: `scripts/rtv-catalog.json`; используемый сайтом манифест:
`src/data/rtv-media.json`. Изображения каналов и фон шапки остаются прежними.
Видео загружается только после активации встроенного борда, для текущего ролика.
Отдельные видео-диалоги удалены: шапка разворачивает фронтальный борд, каналы
переворачиваются по наведению мыши на ПК или по нажатию на телефоне.
Корпус борда выполнен разметкой/CSS с жёлтой рамкой, камерой и маркировкой REMAGO.

Доступны:

- MARKETING: 3 цены, А1, Сегалоптторг, Джили, СЗН, Вакансии, Свинка + маскот.
- SOCIAL: Главный сошиал (`Remago Social.mp4`), Помощь мальчику.
- GBC: Женщина в поле, МЧС (`МЧС_1.mp4`).
- Шапка: Миллениалы и зумеры (`меллиниалы и зумеры.mp4`).

Отсутствуют: Поздравления, Батюшка, Юнихелл, Общий ролик GBC.
Для МЧС предоставлен один файл; разделение на ГТА/Дети не придумано.
NEWS и ENTERTAINMENT ожидают материалов. `соседи.mp4` и
`МТБанк Логойский тракт 37.mp4` не включены: их нет в заданном списке.

## Подготовка видео

Установите FFmpeg с libx264, AAC и FFprobe на машине обработки. Проверьте:

```bash
ffmpeg -version
ffprobe -version
npm run media:prepare
npm run media:check -- --require-encoded
```

При необходимости задайте `FFMPEG`, `FFPROBE`, `RTV_INPUT_DIR` в `.env` (образец
в `.env.example`). Скрипт сохраняет оригиналы в исходной папке без изменений.
После успешной полной обработки он удаляет только созданные им временные копии
`original.mp4` из `public/media/rtv`. Неполные файлы имеют отдельные имена;
манифест заменяется атомарно лишь после обработки всего каталога. Повторный
запуск использует уже готовые версии с тем же хешем исходника и настроек.

Профили:

| Версия | Максимальная область, горизонтальное видео | Вертикальное видео | CRF | Пиковый видеобитрейт | Звук |
| --- | --- | --- | --- | --- | --- |
| desktop | 1920 × 1080 | 1080 × 1920 | 22 | 3,5 Мбит/с | AAC 96 кбит/с |
| mobile | 960 × 540 | 540 × 960 | 24 | 1,2 Мбит/с | AAC 64 кбит/с |

H.264/yuv420p, MP4 с faststart, preset slow, максимум 30 кадров/с.
Маленькие исходники не увеличиваются, пропорции и поворот сохраняются.
Размеры после обработки зависят от содержания. Проверить качество нужно
на текстовых и динамичных сценах перед публикацией; фактического сравнения
сжатых кадров в этой среде не было. Настройки находятся в `scripts/lib/rtv-media.mjs`.
Основание: [документация кодеков FFmpeg](https://ffmpeg.org/ffmpeg-codecs.html),
[faststart](https://www.ffmpeg.org/ffmpeg-all.html).

На телефоне, при Save-Data или медленном соединении выбирается mobile; на
компьютере — desktop. Выбор фиксируется при активации борда. Это два прогрессивных MP4, без адаптивного HLS. После окончания
включается следующий доступный ролик в заданном порядке, затем список повторяется.
Недостающие ролики пропускаются. Возврат к маскоту останавливает и отключает
ресурс видео. Начало без звука позволяет autoplay при наведении; звук включается
кнопкой на борде. При запрете autoplay доступен ручной запуск.

Только для восстановления локальной проверки без кодирования:

```bash
npm run media:prepare -- --stage-originals
```

Эта команда копирует оригиналы без сжатия и **не подходит для публикации**.

## S3 или существующий MinIO

Бинарные файлы хранятся в объектном хранилище, метаданные — в каталоге проекта.
Секреты хранилища не попадают в клиент. Для существующего MinIO используется
тот же интерфейс S3; отдельный сервис приложения и SQL-база не требуются.
Новый сервер MinIO в этой среде не развёрнут.

1. Подготовьте отдельный bucket для медиа и установите AWS CLI на машине выгрузки.
2. Скопируйте `.env.example` в `.env`. Задайте `RTV_S3_BUCKET`, `AWS_REGION` и
   при необходимости `RTV_S3_ENDPOINT`. Учётные данные задавайте через AWS profile
   или серверные переменные `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и
   при необходимости `AWS_SESSION_TOKEN`. Никогда не используйте префикс `VITE_`
   для секретов.
3. Дайте загрузчику доступ на запись только к префиксу `rtv/` и настройте
   публичное чтение медиа через CDN либо bucket policy. Для AWS с публичным
   bucket policy настройка Block Public Access должна допускать такую политику;
   скрипт её не меняет. Альтернатива — закрытый bucket с CDN/OAC.
4. Включите CORS для фактических origin сайта: GET/HEAD, заголовок Range,
   открытые заголовки Accept-Ranges, Content-Length, Content-Range, ETag.
   [S3 CORS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/cors.html),
   [S3 GetObject и Range](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html).

```bash
npm run media:prepare
npm run media:check -- --require-encoded
npm run media:upload -- --dry-run
npm run media:upload
```

Для **выделенного bucket без других правил** можно явно включить
`RTV_ALLOWED_ORIGINS=https://example.com,https://www.example.com` и запустить:

```bash
npm run media:upload -- --configure
```

Этот флаг заменяет CORS и bucket policy, разрешая анонимное чтение только
`rtv/*`. Не используйте его для существующего общего bucket с другими правилами.
По умолчанию загрузка политики не меняет. Bucket скрипт не создаёт.
Для MinIO при необходимости настройте в AWS profile `s3.addressing_style=path`.

Каждый файл имеет версионный путь, Content-Type video/mp4 или image/jpeg и
Cache-Control public,max-age=31536000,immutable. Выгружаются только файлы
текущего манифеста; сторонние объекты и старые версии в bucket не удаляются.

После выгрузки задайте публичный HTTPS URL префикса (не S3 API endpoint,
если тот требует авторизации), например:

```dotenv
VITE_RTV_MEDIA_BASE_URL=https://media.example.com/remago-media/rtv
RTV_MEDIA_PUBLIC_URL=https://media.example.com/remago-media/rtv
RTV_SITE_ORIGIN=https://example.com
```

```bash
npm run media:check -- --remote --require-encoded
npm run typecheck
npm run build
```

Удалённая проверка требует 206 Partial Content и корректные Content-Type,
Content-Range, CORS. При внешнем URL Vite исключает локальные видео из `dist`,
чтобы сайт не дублировал объекты S3. До успешного кодирования внешняя сборка
блокируется; локальная сборка с исходниками работает. Каталог обновляйте и
пересобирайте сайт после загрузки новых роликов.

## Форма и проверка интерфейса

«Узнать подробнее» и «Разместить контент на RTV» открывают «ФОРМА РТВ».
Существующая отправка через почтовое приложение сохранена; серверная запись
заявок в БД не реализована и не заявляется.

Проверить вручную на компьютере и телефоне: открытие каналов, порядок и переход
после окончания, пауза/закрытие/Escape, возврат фокуса, качество и сохранение
позиции, форма RTV, шапка, пустые NEWS/ENTERTAINMENT. Карточки переворачиваются
при наведении и нажатии; видео открывается по нажатию. Браузерная проверка
в текущей среде недоступна из-за ограничений запуска Chromium/сетевых сокетов.
