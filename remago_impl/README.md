# REMAGO

Frontend сайта ООО «Ремаго» на React + TypeScript + Vite.

Проект собран под макеты REMAGO из Figma и текущие reference-assets проекта. RTV подключает видео из локального каталога или S3-совместимого хранилища. Текущее состояние подготовки описано в `RTV_VIDEO_SETUP.md`.

## Стек

- React 19
- TypeScript
- Vite 7
- React Router
- Яндекс.Карты — переход с карты и карточек адресов

## Запуск

Требуется Node.js 22.12+.

```bash
npm install
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173`.

## Production build

```bash
npm run build
```

## Производительность

Для проверки скорости используйте production-сборку (`npm run build`, затем
`npm run preview`), а не dev-сервер. Оптимизированные WebP и responsive-варианты
подключаются через `AssetImage`; оригиналы сохранены. Карта использует статичное превью со ссылкой на Яндекс.Карты; сетевой геокодинг не требуется.
Главная картинка маршрута предзагружается из HTML. Размеры ресурсов и ограничения проверки 4G приведены в
[PERFORMANCE_AUDIT.md](PERFORMANCE_AUDIT.md).

`npm run check:faq` проверяет дословное совпадение FAQ с записанным референсом.
`npm run check:ui` без сервера проверяет девять маршрутов: заголовки, landmark,
уникальность ID, внутренние ссылки и локальные изображения/варианты `srcset`.
Эта проверка не заменяет браузерную проверку геометрии и взаимодействий.

Новые responsive-файлы слайдеров воспроизводятся командой
`python3 scripts/optimize-slider-assets.py` (нужен Pillow). Исходники сохранены.
Результаты прохода 19 октября: [REVIEW_REPORT_2026-10-19.md](REVIEW_REPORT_2026-10-19.md).

`npm run check:performance` собирает production и проверяет все девять маршрутов
на четырёх сетях: **2G, 3G, Slow 4G, Fast 4G**. По умолчанию выполняются три
холодные загрузки каждого маршрута/профиля (108 прогонов), mobile 390×844/DPR 2,
CPU 4×. Профили заданы явно в `scripts/performance-profiles.mjs`.

Первый экран измеряется до прокрутки: тест ждёт видимые изображения, шрифты
и две секунды без новых LCP/CLS-событий. Затем прокручивает страницу,
переключает все слайды, открывает все четыре формы связи и проверяет декодирование картинок
и CSS-фонов. FAQ/формы не отправляются. После измерения первого экрана кэш
включается для обычного повторного использования изображений во время аудита.

JSON и Markdown сохраняются в `reports/performance/`. JSON содержит URL картинок,
ошибки, этапы проверки, размеры/время сетевых запросов и источники скачков макета.
Время полного аудита включает искусственную прокрутку и переключения — это не
время обычной загрузки страницы. Ненулевой код означает недоступную/неполную
проверку либо превышение LCP 3 с / CLS 0,1. Локальный preview не моделирует CDN,
сжатие сервера и задержку реального хостинга. Названия профилей не гарантируют
совпадение с каждым браузерным пресетом.

```bash
cd /home/chaika/Downloads/REMAGO_FIGMA_FULL_SENIOR_RECREATED/remago_impl
npm run check:performance
```

Полный прогон на 2G может занять много времени. Для быстрого первого прохода:

```bash
REMAGO_PERF_RUNS=1 npm run check:performance
# Отдельно desktop и пять повторов:
REMAGO_PERF_VIEWPORT=desktop REMAGO_PERF_RUNS=5 npm run check:performance
# Только выбранные сети:
REMAGO_PERF_PROFILES=4g-slow,4g-fast npm run check:performance
```

Если Playwright отсутствует, установите его один раз:

```bash
npm install --save-dev playwright
npx playwright install chromium
```

`npm run check:performance:logic` проверяет профили и обработку неполных замеров.
В среде Codex сервер/Chromium могут быть заблокированы. Тогда отчёт получает
`unavailable`, времена остаются пустыми. Полный браузерный прогон новой версии
теста в текущей среде не выполнен; требуется запуск в обычном терминале.

## Адаптивная вёрстка

Финальные правила находятся в `src/styles/responsive.css`. Навигация переключается
на меню до 1200 px включительно; первые блоки страниц — на одну колонку до 1100 px.
Сетки карточек, формы, таблица адресов и управление слайдерами адаптируются
дополнительно на 700/600/420 px. Desktop-композиция 1600 px остаётся основой.

`npm run check:responsive` собирает production и запускает Chromium для девяти
маршрутов при 15 ширинах от 320 до 1920 px и в landscape 844×390. Проверяются
горизонтальное переполнение, элементы управления, меню и четыре формы связи.
При доступном браузере создаются скриншоты 320/768/1440 px; JSON сохраняется в
`reports/responsive/`. Нужны Playwright и установленный Chromium, как для
performance-проверки. Это не заменяет проверку Safari/Firefox и реальных устройств.

Текущая среда блокирует сервер через `EPERM`, поэтому браузерная приёмка остаётся
незавершённой. Подробности: [RESPONSIVE_AUDIT.md](RESPONSIVE_AUDIT.md).

## Видео / RTV

На ПК наведение мыши переворачивает карточку канала, на телефоне — нажатие
на маскота. Видео играет внутри фронтального LED-борда REMAGO, без отдельного
окна. Верхний борд по нажатию разворачивается прямо и включает «Миллениалы и
зумеры». Активен один проигрыватель: другой канал останавливает прежний.
На ПК уход курсора с карточки возвращает маскота; на телефоне есть кнопка возврата.

Существующий порядок MARKETING/SOCIAL/GBC сохранён. После завершения включается
следующий доступный ролик; список повторяется по кругу. Отсутствующие материалы
пропускаются, NEWS/ENTERTAINMENT показывают сообщение внутри экрана борда.
Видео стартует без звука; звук включается кнопкой. Предусмотрены управление
браузера, повтор загрузки и ручной запуск при запрете autoplay. Ресурс текущего
видео подключается только после активации. Уход из области просмотра/вкладки
ставит видео на паузу. «Узнать подробнее» открывает прежнюю форму RTV.

Исходники находятся в `../video`. Для обработки нужны полноценные `ffmpeg` и
`ffprobe`. `npm run media:prepare` создаёт две версии H.264/AAC (desktop/mobile)
и постеры, `npm run media:check` проверяет файлы и порядок, `npm run media:upload`
выгружает только сжатые версии в S3/MinIO. Секреты используются только CLI;
в клиент попадает лишь публичный URL. Отдельная БД для каталога видео не нужна.

Подробная настройка, текущее состояние и недостающие ролики: [RTV_VIDEO_SETUP.md](RTV_VIDEO_SETUP.md).

## Макеты и слайдеры

Сверка выполнена по локальным PNG/PDF-экспортам из `../files_for_site`.
Главная и технические характеристики собраны живой React-разметкой.
Базовые стили находятся в `src/styles/global.css`, существующие правила слайдеров —
в `src/styles/reference.css`. Переделка по сводному экспорту 1600 px и адаптивные
правила последнего прохода находятся в `src/styles/design.css`.

Дополнительная сверка по PNG/PDF исправляет конфликты старых CSS-правил,
положение элементов шапки, размеры иллюстрации продукции, типографику и
адаптивные сетки. Исходные значки контактов, галочки услуг и изображения
бордов находятся в `public/assets/design/`; источники указаны в `REFERENCE_AUDIT.md`.

FAQ поддерживает совместный выбор категорий и несколько раскрытых ответов.
На странице продукции стрелки переключают внутренний и наружный борды.
Таблица рекламных адресов, вакансии и тарифы используют HTML-разметку.

`src/components/Carousel.tsx` используется на главной, в партнерах и примерах
рекламных кампаний. Поддерживает стрелки, точки, клавиши ←/→ и свайп.
Каждый тип слайдера сохраняет размеры карточек при переключении; изображения
показываются без растяжения. Рекламные изображения и соответствующие бренды
заданы вместе в `src/data/campaigns.ts`.

Слайдеры сцен, партнёров, рекламных кампаний, адресов и типов продукции используют
общую логику переходов: 400 мс, мягкое смещение и затухание. Изображения соседних
слайдов загружаются и декодируются заранее. Повторные нажатия сохраняют последний
запрошенный слайд, не обрывая текущую анимацию. При `prefers-reduced-motion` переход
происходит без анимации. Вертикальная прокрутка и pinch-to-zoom не переключают
слайды в каруселях со свайпом.

`npm run check:carousels` проверяет очередность переключений, быстрые нажатия,
смену направления, границы списка, выбор точками и режим уменьшения анимации.
Это проверка логики; визуальная плавность требует приёмки в браузере.

Нажатие на карту и «Показать на карте» открывает пользовательскую карту Яндекса, указанную в задании. Все 25 карточек адресов содержат фото и характеристики. Таблица, стрелки и точки выбирают адрес; значки показывают пояснения из «Обозначения.pdf».

## Формы связи

Кнопки «Заказать звонок», «Служба поддержки», «Узнать подробнее» в RTV и «Коммерческое предложение» в услугах открывают соответствующие диалоги. Формы RTV и КП используют существующее оформление форм связи.
Форма проверяет обязательные поля и номер телефона. Отправка открывает почтовое
приложение с подготовленным письмом на `remago@bk.ru`; письмо необходимо отправить
в почтовом приложении. Сайт не заявляет, что заявка уже доставлена.
Файлы юридических документов не предоставлены: ссылки футера готовят запрос
соответствующего документа по электронной почте. Глобус в шапке обозначает
русский язык сайта; переключение языков не реализовано.

## Проверка соответствия

TypeScript и production build проходят. Серверная проверка охватывает все маршруты
и локальные пути изображений. Проверка в браузере и pixel diff в текущей среде
заблокированы системными ограничениями запуска сервера и Chromium. Поэтому
совпадение 1 в 1 требует проверки в обычном браузере. Подробности и оставшиеся
отличия карты/форм описаны в `REFERENCE_AUDIT.md`.
