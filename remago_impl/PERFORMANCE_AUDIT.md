# Загрузка всех страниц — 11 октября 2026

Повторная попытка браузерного замера: production build проходит, но `vite preview`
возвращает `listen EPERM: operation not permitted 127.0.0.1:4173`; Chromium
завершается до открытия страницы (`crashpad: setsockopt: Operation not permitted`).
Значения LCP/FCP/CLS не получены. Подготовлен автоматический прогон
`npm run check:performance`: девять маршрутов, пять повторов, кэш отключён,
390×844/DPR 2, сеть 1,6/0,75 Мбит/с и 150 мс, CPU 4×. Синтаксис и обработка
недоступного сервера проверены; полноценная работа сценария требует запуска
в обычном терминале с доступным Chromium. Отчёт сохраняется даже при ошибке,
а неподтверждённые значения не заменяются расчётными.

Автоматизация использует [Playwright CDPSession](https://playwright.dev/docs/api/class-cdpsession)
для ограничений Chrome и [LargestContentfulPaint](https://developer.mozilla.org/en-US/docs/Web/API/LargestContentfulPaint)
для наблюдения LCP до `load` + 3 секунды без прокрутки или взаимодействий.

Оптимизированы ресурсы всех восьми страниц и 404. Время 3 секунды не измерено: запуск браузера и локального сервера в этой среде ограничен. Ниже приведены проверенные размеры файлов, а не результаты Lighthouse или фактические времена на 4G.

## Что изменено

- Общий `AssetImage` подставляет оптимизированные изображения, задаёт исходные размеры для резервирования места и использует `loading="lazy"`/`decoding="async"`. Главные иллюстрации явно загружаются сразу с `fetchPriority="high"`; логотип шапки тоже загружается сразу. Ширины, карточки, текст и CSS типографики сохранены.
- Созданы 66 полноразмерных WebP без потери пикселей: 25 377 539 → 17 278 106 байт. Оригинальные PNG остаются в проекте. Дополнительно созданы 145 вариантов шириной 384/640/960/1280 px для 39 изображений, включая уже существовавшие WebP главной. Варианты используют качество 90 и Lanczos; они не являются побитово одинаковыми с исходником. Прозрачность проверена отдельно.
- `srcset` выбирает размер под экран и DPR; `sizes` задаёт 100vw до 900 px и 50vw выше. Это консервативная оценка для общих иллюстраций. Предзагрузка слайдов использует те же варианты, чтобы не скачивать дополнительно полноразмерный PNG.
- Фон главной `partner-waves.svg` размером 3,4 МБ и нижний фон CTA подключаются при приближении секции к экрану (300 px). Геометрия псевдоэлементов сохранена. Сами SVG не переделаны.
- Фоновая предзагрузка соседей слайдеров начинается после события `load`, в свободное время браузера; у общих каруселей дополнительно требуется приближение к экрану. Подготовка непосредственно запрошенного слайда сохраняется.
- Рекламная страница и Leaflet вынесены в отдельный динамический пакет. На остальных страницах он не нужен. Основной JS: **479,9 → 331,1 kB** без сжатия; новый рекламный пакет — 167,5 kB. Перенос уменьшает начальную загрузку остальных страниц, а не суммарный код рекламной страницы.
- Google Fonts подключается из HTML с `preconnect`, вместо цепочки `CSS → @import → CSS шрифтов`. Сохранён Roboto Condensed 400/500/600/700/800 и `display=swap`. Неиспользуемый Inter исключён из запроса. Самостоятельно разместить шрифты не удалось: среда не разрешает DNS-запрос curl к Google Fonts.

Описание атрибутов изображений: [MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img). Отложенное подключение компонента: [React lazy](https://react.dev/reference/react/lazy).

## Как подтвердить 3 секунды

Проверять production, а не `npm run dev`: `npm run build`, затем `npm run preview` или опубликованную сборку `dist/`. В DevTools: одинаковые viewport/DPR, профиль 4G, отключённый кэш, холодная загрузка каждого маршрута; повторить несколько раз. Сравнивать LCP и доступность первого экрана. Показатель Network Finish включает фоновые и отложенные запросы и не обозначает момент готовности первого экрана.

На хостинге должны реально работать Brotli/gzip для JS/CSS/SVG и кэширование. Хешированные файлы `dist/assets/*.js` и `*.css` можно кэшировать длительно; HTML и изображения со стабильными именами должны корректно обновляться при новой публикации. Числа gzip из Vite обозначают потенциальный сжатый размер, а не подтверждают настройку сервера. Адрес и конфигурация опубликованного сайта не предоставлены; хостинг не изменён.


## Дополнительная оптимизация и расширенный тест (11 октября 2026)

- Главная картинка каждого из восьми маршрутов предзагружается из HTML с теми же
  `srcset`/`sizes`, что у `<img>`, до запуска React. Это устраняет ожидание запуска
  приложения перед обнаружением картинки; влияние на секунды ещё не измерено.
- Спекулятивная загрузка соседних слайдов ждёт декодирования изображений с высоким
  приоритетом. Размеры карточек, текст и длительность переходов сохранены.
- Страница рекламы рендерится сразу; пустой Suspense-блок убран. Leaflet и его CSS
  загружаются при приближении к карте. Первый основной JS теперь 349,48 КБ
  (gzip 106,12 КБ); отдельный Leaflet 149,90 КБ (gzip 43,48 КБ). Дополнительные
  18 КБ начального JS содержат страницу рекламы и позволяют убрать подмену
  пустого блока. Причину прежнего CLS нужно подтвердить новым браузерным отчётом.
- RTV-logo получает `sizes` по фактической ширине 140/190 px вместо половины экрана.
- Фон волн: 3 514 149 → 3 026 722 байта; gzip 996 771 → 956 139 байт.
  Удалены 12 085 замкнутых линий нулевой площади без stroke. Оригинал сохранён.
  Рендер librsvg/Cairo до/после сравнен по всем RGBA-пикселям при 1600×480,
  3200×960, 4800×1440: полное совпадение. Это проверка эквивалентности ресурса,
  а не браузерная визуальная приёмка страницы.
- Офлайн проверены 407 файлов (128 PNG, 259 WebP, 20 SVG) и 86 записей manifest:
  растровые файлы декодируются, SVG парсятся, пути/размеры manifest корректны.
  Результат: `reports/performance/image-integrity.json`, ошибок нет.

Новый `check:performance` охватывает 2G/3G/Slow 4G/Fast 4G, все девять маршрутов,
по три повтора (108). Первый экран ждёт видимые картинки, шрифты и стабильность
LCP/CLS. Дальше проверяются прокрутка, каждый слайд, оба диалога, CSS-фоны и
изображения карты после завершения геокодирования. Сетевые ошибки/таймауты не
считаются успехом. JSON хранит URL/фазы, запросы/байты, источники CLS; Markdown
сводит результаты по профилям. Метки карты проверяются отдельно: геокодер может
не найти адрес, поэтому число меток не подменяется выдуманными координатами.

Полный аудит включает искусственные действия и не является обычным временем
загрузки. Профили воспроизводимы, но не гарантируют эквивалентность конкретному
оператору/браузерному пресету. На 2G цель 3 секунды может быть недостижима.
